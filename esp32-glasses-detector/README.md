# ESP32 휴대용 스마트글래스 탐지/추적기

주변의 BLE 신호에서 **스마트글래스(Ray-Ban/Oakley Meta, Even Realities, Snap Spectacles 등)만** 골라 화면에 보여줍니다. 배터리로 들고 다니면서 신호 세기로 **위치를 따라갈 수 있고**, 폰에 이미 연결되어 사용 중인 안경도 최대한 잡도록 맞춰 두었습니다.

## 하드웨어 두 가지 경로

| | ⭐ 화면 일체형 (추천, 간단) | 흑백 OLED 조립형 |
|---|---|---|
| 보드 | **XIAO ESP32-S3 Plus + 1.14" IPS** | XIAO ESP32S3 + 별도 OLED |
| 화면 | 컬러 TFT 내장(ST7789 135×240) | 0.96" 흑백 OLED |
| 버튼 | 3개 내장 | BOOT 버튼 1개 |
| 배터리 측정 | 내장(D16) | 저항 2개 추가 |
| 배선 | 거의 없음 | OLED·버튼·저항 납땜 |
| 빌드 환경 | `xiao_s3_plus_114` | `xiao_esp32s3` |
| 하우징 | `hardware/housing_plus.scad` (크래들) | `hardware/housing.scad` |

- **화면 일체형**: 부품이 보드 하나로 끝나 가장 쉽습니다. 컬러라 "사용 중" 안경은 빨강, 대기는 초록으로 보여줍니다. → 빌드: `pio run -e xiao_s3_plus_114 -t upload`
- **OLED 조립형**: 아래 1~8장 설명은 이 경로 기준입니다. 소리(가이거 추적)·진동모터를 붙이기 좋습니다.

두 경로 모두 **탐지 로직은 동일**합니다(`detector.cpp`/`signatures.h`). 화면만 다릅니다.

## 이어폰·워치 속에서 안경만 골라내기 (+ 카메라 의심 탐지)

주변엔 이어폰·헤드폰·워치 등 BLE 기기가 많아서, 다음을 조합해 **안경만** 남깁니다.

1. **BLE 화이트리스트**: 알려진 안경 제조사 ID/이름(메타·Even·Vuzix·Snap 등) → 안경으로 표시
2. **BLE 블랙리스트**: 이어폰/워치/폰/스피커 제조사(Apple·Samsung·Bose·Sony·Garmin·Sonos…) → 아예 무시
3. **미확인(`?`) 버킷**: 무명 중국 카메라가 자주 쓰는 BLE 칩(Telink·Beken·Bluetrum·Barrot·Realtek)·`0xFFFF`를 쓰는 **연결형** 기기 → "미확인 무선기기(낮은 확신)"로 따로 표시해 직접 판단
4. **WiFi 카메라 AP 스캔**: 스파이 카메라는 영상 전송에 WiFi 핫스팟을 쓰는 경우가 많습니다. 주변 AP를 스캔해 카메라형 SSID/OUI를 찾아 화면 하단에 **`WiFi cam? N`** 으로 경고 (`src/wifi_scan.cpp`에서 키워드 수정 가능)

> ⚠️ **한계**: 무명 카메라는 자기를 "안경/카메라"라고 밝히지 않아 BLE만으로 100% 확정은 불가능합니다. 위 4개는 "확정"이 아니라 "후보 좁히기 + 의심 표시"입니다. 확실한 숨은 카메라 탐지는 렌즈 IR 반사 탐지 같은 물리적 방법을 병행해야 합니다.

## 1. 부품 (OLED 조립형 기준)

| 부품 | 추천 | 비고 |
|---|---|---|
| 보드 | **Seeed XIAO ESP32S3** | 작고, LiPo 충전 회로가 들어 있고, BLE 5 확장 광고와 Coded PHY(장거리)를 지원합니다 |
| 화면 | 0.96" SSD1306 128x64 I2C OLED | 1.3" SH1106도 가능 (`-DOLED_SH1106=1`) |
| 배터리 | 3.7V LiPo 500~1000mAh | XIAO 뒷면 BAT+/BAT- 패드에 납땜 |
| 소리 | 3.3V 액티브 부저 (또는 진동모터 + NPN 트랜지스터) | 주머니 속에서는 진동모터가 편합니다 |
| 배터리 측정 | 100kΩ 저항 2개 | 1/2 분압 |
| 스위치 | 슬라이드 스위치 | 배터리 + 선에 직렬로 연결 |

다른 보드(ESP32 DevKit, S3 DevKitC, C3)도 지원합니다. ESP32-S2에는 블루투스가 없어서 사용할 수 없습니다.

## 2. 배선 (XIAO ESP32S3 기준)

```
OLED VCC ── 3V3        OLED GND ── GND
OLED SDA ── D4 (GPIO5) OLED SCL ── D5 (GPIO6)
부저  (+) ── D2 (GPIO3) 부저  (-) ── GND
LiPo(+) ── 스위치 ── BAT+ 패드     LiPo(-) ── BAT- 패드
BAT+ ── 100k ──┬── 100k ── GND
               └── A0 (GPIO1)     ← 배터리 전압 측정
```

버튼은 보드에 이미 있는 **BOOT 버튼**을 씁니다. 다른 보드의 핀은 `platformio.ini`의 각 환경에 적혀 있습니다.

## 3. 빌드 및 업로드

```bash
pip install platformio
cd esp32-glasses-detector
pio run -e xiao_esp32s3 -t upload     # 다른 보드: esp32s3 / esp32c3 / esp32dev
pio device monitor
```

## 4. 사용법

**목록 화면**
```
GLASSES: 2          82%
───────────────────────
*Ray-Ban/Oakley  -63^     ← * = 폰과 연결되어 사용 중(추정), ^ = 가까워지는 중
 Even G1         -81
*=in use  hold=track
```
- 버튼을 **짧게** 누르면 다음 대상을 선택합니다.
- **0.7초 이상** 누르면 선택한 대상의 추적 모드로 들어갑니다.
- 신호가 잠시 끊긴 대상은 RSSI 대신 마지막으로 본 시간(`45s`)을 보여줍니다. 3분 동안 기억합니다.

**추적 모드**
```
Ray-Ban/Oakley        82%
───────────────────────
-63  dBm         CLOSER
     ~3m        IN USE?
[██████████░░░░░░░░░░░]
live  HIGH  #3
```
- 신호가 강해질수록 **삑삑 소리가 빨라집니다.** 약 -95dBm에서는 1.5초에 한 번, -45dBm에서는 0.08초에 한 번 울립니다.
- 천천히 걸으면서 소리가 빨라지는 방향으로 가면 됩니다. 몸이 신호를 막으므로, 제자리에서 한 바퀴 돌면서 가장 강한 방향을 찾는 것도 좋습니다.
- 짧게 누르면 소리를 켜고 끕니다. 길게 누르면 목록으로 돌아갑니다. 어느 화면에서든 3초 누르면 소리를 켜고 끕니다.

## 5. 핵심: 폰에 연결된 안경 찾기

### 왜 어려운가
안경은 폰과 **연결되기 전**에는 폰이 빨리 찾을 수 있도록 20~100ms 간격으로 광고를 쏟아냅니다. **연결된 후**에는 데이터가 폰과의 연결 채널로만 오가기 때문에 광고가 다음 중 하나로 바뀝니다.

1. 광고를 **완전히 멈춤**: ESP32로는 원리적으로 볼 수 없습니다 (아래 7번 참고).
2. 광고 간격을 **1~10초로 늘림**: 잡을 수 있지만 놓치기 쉽습니다.
3. **연결 불가능(non-connectable)** 광고나 **BLE 5 확장 광고**로 바꿈: BLE 4.2 칩은 확장 광고를 아예 받지 못합니다.

공개된 탐지 앱들이 실제 사용 중인 Meta 안경을 잡아내는 걸 보면, Meta 안경은 연결된 동안에도 2번이나 3번처럼 광고를 계속 보내는 것으로 보입니다. 다만 직접 확인한 것은 아니므로, 6번의 방법으로 내 안경에서 확인해 보시기를 권장합니다.

### 이 펌웨어에서 대응한 방법
| 문제 | 대응 |
|---|---|
| 드문 광고를 놓침 | 스캔 **듀티 100%** (window = interval). 쉬는 시간 없이 계속 수신합니다 |
| 약한 신호 | RSSI 기준을 -95dBm까지 낮췄습니다. S3/C3에서는 **Coded PHY(장거리)** 도 수신합니다 |
| BLE 5 확장 광고 | S3/C3 빌드에서 `CONFIG_BT_NIMBLE_EXT_ADV`를 켜서 확장 광고도 수신합니다 |
| 몇 초에 한 번만 보임 | 3분 동안 기억하고, 마지막으로 본 시간을 표시합니다 |
| 연결 중 MAC 주소 변경 (약 15분마다) | 제조사 ID와 데이터 구조로 만든 **지문**으로, 사라진 직후 같은 지문의 새 주소가 나타나면 같은 기기로 이어서 추적합니다 |
| 연결 상태 판단 | 광고 간격과 connectable 여부로 **`IN USE?`(사용 중 추정)** 와 `IDLE`을 구분합니다 |

### 사용 상태 판정 기준 (`detector.cpp`의 `usageState()`)
- 연결 불가능 광고이거나, 평균 간격이 900ms 이상이면 → `IN USE?` (폰과 연결되어 있을 가능성이 높음)
- 연결 가능 광고이고, 간격이 400ms 미만이면 → `IDLE` (연결 안 됨 또는 페어링 대기)
- 그 사이는 `?`

이 기준은 일반적인 BLE 기기의 동작을 바탕으로 정한 **추정값**입니다. 기종마다 다르므로 아래 방법으로 보정하는 것을 권장합니다.

## 6. 내 안경으로 보정하기 (권장)

시리얼에는 안경으로 판정된 패킷이 모두 CSV로 출력됩니다 (`OBS,...` 줄).

```bash
pio device monitor | tee log.txt
#  ① 폰 블루투스를 끈 상태로 2분
#  ② 폰 블루투스를 켜서 안경이 연결된 상태로 2분
#  ③ 안경으로 사진/음악/AI를 사용하면서 2분
python3 tools/analyze_log.py log.txt 30     # 30초 구간별로 분석
```

출력 예시:
```
=== 대상 #1  company=0x0D53  이름=RB Meta  패킷 412개
        구간  패킷  간격중앙값  RSSI평균  connectable  legacy
     0-30 s   300      100ms     -60.0        100%    100%   ← 연결 전
    30-60 s    15     2000ms     -71.0          0%    100%   ← 연결 후
```
연결 후의 간격과 connectable 값을 보고 `usageState()`의 기준값을 조정하면 됩니다. 아무 패킷도 잡히지 않는 경우에는 `config.h`의 `RAW_DUMP = true`로 바꿔서 모든 패킷을 확인해 보세요. 연결 중에는 다른 Company ID나 이름 없이 광고할 수도 있습니다.

## 7. ESP32의 한계와 다음 단계

- 안경이 연결된 후 **광고를 완전히 멈추는 기종**은 ESP32로 잡을 수 없습니다. ESP32의 블루투스 칩은 다른 기기끼리 주고받는 연결 패킷을 엿듣는 기능(promiscuous 모드)을 제공하지 않기 때문입니다.
- 그런 기종까지 잡으려면 **nRF52840 동글 + [Sniffle](https://github.com/nccgroup/Sniffle)** 같은 BLE 스니퍼 펌웨어가 필요합니다. 폰이 안경에 연결하는 순간의 `CONNECT_IND` 패킷을 잡으면, 그 연결을 계속 따라가면서 연결 중에도 RSSI를 측정할 수 있습니다. 이 탐지기가 광고 단계에서 안경의 주소를 알아두고, 스니퍼가 연결을 따라가는 방식으로 두 장비를 함께 쓸 수 있습니다.
- Ray-Ban Meta의 음악/통화 오디오는 **클래식 블루투스**로 전송됩니다. 연결된 클래식 기기는 검색에 응답하지 않아서 ESP32로는 보이지 않습니다.
- 사람 몸, 가방, 벽 때문에 RSSI가 10~20dB씩 쉽게 변합니다. 거리 표시는 대략적인 값입니다.
- 같은 모델 두 대가 동시에 주소를 바꾸면 지문 추적이 섞일 수 있습니다.
- Even G1은 왼쪽/오른쪽 다리가 각각 광고하므로 2개로 보일 수 있습니다.
- 수신만 하고 상대 기기에 접속하거나 간섭하지 않습니다.

## 8. 배터리 사용 시간

스캔 듀티 100%에서 소비 전류는 XIAO ESP32S3 + OLED 기준으로 약 80~110mA입니다. 1000mAh 배터리로 약 8~10시간 사용할 수 있습니다. 실측값이 아닌 추정치입니다. 더 오래 쓰려면 `display.cpp`에서 화면 밝기(`setContrast`)를 낮추세요.

## 파일 구성

| 파일 | 내용 |
|---|---|
| `src/config.h` | 핀, 기준값 설정 |
